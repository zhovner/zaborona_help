# Скрипты для MikroTik (RouterOS 7)

## zaborona-cert-autoupdate.rsc

Слежение за клиентским сертификатом `zaborona-help.crt` и его автоматическая замена.

### Проблема

Сертификат, который лежит в корне этого репозитория и используется во всех инструкциях, выдан **19.05.2017 сроком на 10 лет**:

```
notBefore=May 19 19:44:12 2017 GMT
notAfter=May 17 19:44:12 2027 GMT
```

**17 мая 2027 года** он истечёт, и туннели перестанут подниматься у всех сразу. Отдельного внятного сообщения про истёкший сертификат в логе RouterOS не будет — со стороны это выглядит как «настроено правильно, но не работает».

Проверить свой сертификат:

```
/certificate print detail where common-name="public"
```

### Установка

Загрузить файл на роутер (Files) и выполнить:

```
/import file-name=zaborona-cert-autoupdate.rsc
```

Создаётся скрипт `zaborona-cert-autoupdate` и еженедельное задание `zaborona-cert-check-job`.

Скрипт рассчитан на имена из основной инструкции — интерфейс `zaborona`, сертификат `zaborona-help.crt`. Если у вас другие, поправьте переменные в начале скрипта.

Если у вас установлен [скрипт автообновления маршрутов](https://github.com/zhovner/zaborona_help/wiki/MikroTik-Script-AutoUpdate-Routes-(RouterOS-7)), задайте заданиям разное время, чтобы они не пересекались.

### Проверка

```
/system script run zaborona-cert-autoupdate
/log print where message~"ZABORONA-CERT"
```

Первый запуск создаёт эталонный снимок (`reference snapshot created`), последующие должны писать `no change, published certificate is identical`.

### Что происходит при появлении нового сертификата

1. Скачивается ключ, импортируются сертификат и ключ.
2. Проверяются три условия: издатель содержит `Zaborona.help`, приватный ключ подошёл, новый сертификат живёт дольше текущего. Если хоть одно не выполнено — всё откатывается, ничего не меняется.
3. Старый сертификат переименовывается в `zaborona-help-old-<дата>`, новый занимает его место, ovpn-клиент перепривязывается и переподключается.
4. Через 30 секунд проверяется состояние туннеля. Если не поднялся — **старый сертификат возвращается автоматически**.

Дополнительно: за 8 недель до истечения каждый запуск начинает писать в лог строку уровня `error` с предупреждением.

### Замечание по реализации

Сравнение идёт по содержимому файла, а не через импорт во временную запись с последующим сравнением отпечатков. Так сделано вынужденно: **RouterOS отказывается импортировать сертификат, который уже установлен**, и возвращает `certificates-imported: 0`.

### Что протестировано

Проверено на RB3011UiAS, RouterOS 7.21.5.

Протестированы: обнаружение отсутствия изменений, обнаружение изменения, валидация, аварийный выход без побочных эффектов, а также механика замены (переименование сертификата, перепривязка ovpn-клиента, переподключение) — вручную на существующем сертификате.

Полный путь замены на настоящем новом сертификате протестировать невозможно, пока такой сертификат не опубликован. Это стоит учитывать.
